1. PROJECT OVERVIEW
================================================================================

Project Name    : ViserTrip
Project Type    : Multi-Tenant SaaS Travel, Tour Booking & Visa Management Platform

ViserTrip is a complete SaaS-based platform where multiple travel agencies can
subscribe and use the system independently.

Each travel agency receives:
  - Its own Admin Panel
  - Its own separate PostgreSQL database
  - Its own users and customers
  - Its own Travel & Visa Management System
  - Its own website / landing page
  - CMS functionality to manage its website
  - Individual domain or subdomain support
  - Individual packages and subscription
  - Separate bookings and payments
  - Separate branding and website settings

The platform has three main levels:
  1. Super Admin
  2. Agency Admin / Tenant
  3. Customer / User

# Database Setup and domain

In your project, individual databases for new agencies are created and isolated automatically by your Django backend whenever a new agency subscribes.

Here is how the automatic process works under the hood, along with the critical cPanel/PostgreSQL setup steps required for it to run smoothly on your server.

1. How It Works Automatically in Your Project
When a new agency subscribes, your application executes the 

provision_tenant
 pipeline (located in 

apps/tenants/provisioning.py
):

Automatic Database Creation (CREATE DATABASE): Django connects to your PostgreSQL server using the master database user set in your .env file and executes:

sql
CREATE DATABASE "travel_agency_slug";
This creates a completely separate, clean PostgreSQL database just for that agency.

Automatic Table Migration (

run_tenant_migrations
): Django runs migrations on the newly created database alias (tenant_agencyslug), automatically setting up all required agency tables (Travel Packages, Visas, Bookings, CMS, Payments, etc.).

Automatic Admin & Subdomain Provisioning:

Creates the default agency admin user and sets up their initial CMS settings.
Assigns them a subdomain (e.g., agencyname.yourdomain.com).
Dynamic Data Isolation (TenantDatabaseRouter): When a user or agency admin visits agencyname.yourdomain.com, the Tenant Middleware detects the agency and routes all SQL queries exclusively to that agency's individual PostgreSQL database (

apps/tenants/routers.py
).

2. Required cPanel / PostgreSQL Configuration
For this automatic database creation to work on your cPanel server without throwing permission errors:

A. Grant CREATEDB Permission to your PostgreSQL User
Standard cPanel database users often do not have permission to create databases dynamically via code.

Open your PostgreSQL interface (or connect via SSH / Terminal to PostgreSQL) as superuser and execute:
sql
ALTER USER your_db_username WITH CREATEDB;
(Replace your_db_username with the DB_USER defined in your Django .env file).

B. Wildcard Subdomain in cPanel
Since every agency gets their own subdomain (agency1.yourdomain.com, agency2.yourdomain.com):

Log into cPanel.
Go to Domains / Subdomains.
Create a Wildcard Subdomain: * (e.g., *.yourdomain.com).
Set its Document Root to point to your Django application directory.
Summary Checklist for Deployment
Requirement	Setting / Command
PostgreSQL User Privilege	Must have CREATEDB (ALTER USER db_user WITH CREATEDB;)
.env Configuration	DB_HOST=127.0.0.1 (or localhost), DB_PORT=5432, DB_USER, DB_PASSWORD
Subdomain Routing	Setup *.yourdomain.com wildcard in cPanel DNS/Subdomains
